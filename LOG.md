# Build log (one line per session: the date, what shipped, what I learned)

- 2026-10-02: Plan made. Serverless, a $0 hard constraint, milestones M0 to M6. The account got upgraded to the Paid plan by accident, so guardrails moved to the top of the list.
- 2026-10-02: GATE 0 done. Root MFA (passkey, no root keys), a $1 monthly budget (50% and 100% actual, 100% forecast) and a Cost Anomaly alert at $1 (daily email). Billing entity: Amazon Web Services India Private Limited. Learned: budgets only notify, with a delay. They don't stop spend.
- 2026-10-05: Identity Center user and SSO CLI profile (ap-south-1), Terraform skeleton with two roots, and the guardrails stack applied and tested: $1 budget -> SNS -> kill switch, and the budget action locks the deploy role. Learned: Terraform state and plan/apply, why guardrails live in their own root, and that the account's Lambda limit of 10 blocks reserved concurrency (ADR-003).
- 2026-10-06: ADR-001 written (serverless + Terraform), so M0 is complete. Learned: always-on resources bill by the hour, DynamoDB gives up ad-hoc SQL in exchange for per-use cost, and plan-before-apply is the main thing Terraform gives you.
- 2026-10-07: GATE 2. Pose detection runs in the browser for privacy (ADR-002). Frontend scaffolded; the measurement maths is ported to TypeScript and matches the Python prototype on the fixtures. Learned: keep model calls apart from the pure maths, so the maths can be tested without a model.
- 2026-10-07 (later): Fixed two measurement issues. Shoulders are now measured edge to edge with a plausibility check, and widths are divided by the hip joint width instead of converted to centimetres (ADR-004). Learned: a photo shows shape, not size. Ratios cancel out pixels, and a skeletal ruler makes widths comparable between photos.
- 2026-10-08: Scoring module. The shoulder-to-waist ratio from the first photo, then the percent change against it with a ±2% noise band, documented in docs/scoring.md. M1 complete. Learned: a score needs a reference point, and a percent change is more honest than made-up points.
- 2026-10-10: README with architecture diagrams. Designed the M2 data model and API contract (docs/api.md, ADR-005): the user ID comes only from the token, the server sets the timestamp, the browser sends pixel ingredients, scores are recomputed on read and flagged photos are kept. Learned: the API is a trust boundary, and since photos are discarded, a number that isn't saved is gone for good. Then built the API handler locally: token verification with PyJWT, validation, the DynamoDB store and history scoring, with 63 tests using fake keys, a fake store and a fake clock.
- 2026-10-10 (later): M2 deployed. The protected data stack (DynamoDB provisioned inside the free tier, plus a Cognito user pool, both deletion-protected) and the API Lambda behind a public Function URL. Smoke-tested from sign-up to a saved measurement. Learned: on-demand DynamoDB isn't free, and protecting data also means protecting what its keys point to.
- 2026-10-11: M3 step 1. LiftLens theme, the app's own sign-in screens with Amplify (SRP) and a History screen that reads the live API through a dev proxy. Signed in with a real account. Learned: the app is a set of states, and an explicit Save stops a bad first photo from becoming the baseline.
- 2026-10-11 (later): M3 step 2, guided capture. Propped phone, front camera, a body outline, tap Start for a 10 s countdown with beeps, then review with Retake or Use photo, and upload as a fallback. The photo stays in memory and the camera stops after the shot. Tested live on a laptop. Learned: the photo is checked after the shot because live checking costs battery and complexity, and an outline only lines up if the frame has the same shape as the picture.
- 2026-10-11 (UI): History polish. A trend chart with the ±2% noise band and the baseline, and the change since the last check-in (same noise rule, flagged photos skipped). A front body map highlights only what V1 measures (shoulders, waist) and marks everything else as not measured; it was then redrawn as an anatomical figure, with a back view where every muscle is grey because there's only a front photo. The check-in setup tips became icon tiles with short text (lucide-react added). The review photo grew to nearly full height with icon check chips. The camera screen got a bigger picture, a bolder outline and a large corner countdown you can read from 2 m. Sign-in and sign-up gained an intro panel (track progress from photos, an explainable score, the photo stays private). History got a sparkline and facts row on the top card, and the body map now starts collapsed. Learned: a visual should only show what the data supports. Per-muscle ratings without a measurement behind them would be made-up numbers.
- 2026-10-11 (step 3): Built the measuring step. The models preload when check-in opens, a scan shows the live steps, and shoulder and waist lines are drawn over the photo. Meaningless photos get a retake (nobody found, joints cut off, no outline); a suspicious shoulder outline can be saved as flagged. Learned: flag what's suspicious, retake what's meaningless.
- 2026-10-15: M3 complete. front2.png measured 1.78 in the browser (Python reference 1.785) and was saved. History shows "no clear change" from the server's sinceLast, and the camera light goes off after capture. Learned: only a real-photo test proves the whole chain works.
- 2026-10-15 (calibration): Calibration photos showed the outline model measuring furniture as part of the body. Switched to the pose model's own outline (ADR-007; GPU and a 2048 px cap after a freeze), with one baseline per method. Calibrated the noise threshold to ±2.4% from 10 repeat photos and deployed. Learned: look at what the model saw before changing anything, and decide the rule before seeing the numbers.
- 2026-10-17: Built the catch-and-guide checks (sideways, back, too far, hand at shoulder, arms touching, pose against the baseline; ADR-008), testing each threshold on real photos first. Repeat photos from one session showed that the waist row sitting on the waistband causes most of the wobble (at a 55% row the SD went from 3.58% to 1.13%); this still has to be validated on a fresh session. Learned: test a threshold on known-good photos before trusting it, and never trust a winner picked from the same data.
- 2026-10-20: Cleaned up the wording across the docs so they share one plain style, and brought the project story's status and test counts up to date (89 TypeScript, 112 Python). Learned: a merged PR keeps its branch name in the history, so name each branch after what it does.
