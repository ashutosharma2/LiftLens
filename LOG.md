# Build log (one line per session: date — what shipped — what I learned)

- 2026-10-02 — Plan made: serverless, $0 hard constraint, M0–M6 milestones. Account accidentally upgraded to Paid plan; guardrails moved to top priority.
- 2026-10-02 — GATE 0 done: root MFA (passkey, no root keys), $1 monthly budget (50%/100% actual + 100% forecast), Cost Anomaly alert at $1 (daily email). Billing entity: Amazon Web Services India Private Limited. Learned: budgets only notify (with delay), they don't stop spend.
- 2026-10-05 — Identity Center user + SSO CLI profile (ap-south-1), Terraform skeleton (two roots), guardrails stack applied and tested: $1 budget -> SNS -> kill switch, budget action locks the deploy role. Learned: Terraform state and plan/apply, why guardrails live in their own root, account Lambda limit of 10 blocks reserved concurrency (ADR-003).
- 2026-10-06 — ADR-001 written (serverless + Terraform); M0 complete. Learned: always-on resources bill hourly, DynamoDB trades ad-hoc SQL for per-use cost, plan-before-apply is Terraform's core value.
- 2026-10-07 — GATE 2: pose detection runs in the browser (ADR-002, privacy). Frontend scaffolded; measurement maths ported to TypeScript and matches the Python prototype on the fixtures. Learned: separate model calls from pure maths so the maths is testable without a model.
- 2026-10-07 (later) — Fixed two measurement issues: shoulders now edge to edge with a plausibility check, and widths normalised by hip joint width instead of centimetres (ADR-004). Learned: a photo shows shape not size; ratios cancel pixels, and a skeletal ruler makes widths comparable across photos.
- 2026-10-08 — Scoring module: shoulder-to-waist ratio from the first photo, then percent change vs the first photo with a ±2% noise band; documented in docs/scoring.md. M1 complete. Learned: a score needs a reference point, and a percent change is more honest than invented points.
- 2026-10-10 — README with architecture diagrams; M2 data model and API contract designed (docs/api.md, ADR-005): user ID only from the token, server timestamp, browser sends pixel ingredients, scores recomputed on read, flagged photos kept. Learned: the API is a trust boundary, and with photos discarded, unsaved numbers are lost forever. Then built the API handler locally: token verification with PyJWT, validation, DynamoDB store and history scoring, 63 tests with fake keys, store and clock.
- 2026-10-10 (later) — M2 deployed: protected data stack (DynamoDB provisioned inside the free tier + Cognito user pool, both deletion-protected) and the API Lambda behind a public Function URL; smoke-tested sign-up to saved measurement. Learned: on-demand DynamoDB isn't free, and protecting data means protecting what its keys point to.
- 2026-10-11 — M3 step 1: LiftLens theme, own sign-in screens with Amplify (SRP) and a History screen reading the live API through a dev proxy; signed in with a real account. Learned: the app is a set of states, and an explicit Save stops a bad first photo becoming the baseline.
- 2026-10-11 (later) — M3 step 2: guided capture — propped phone, front camera, body outline, tap Start then a 10 s countdown with beeps, review with Retake / Use photo, upload as a fallback; the photo stays in memory and the camera stops after the shot. Tested live on a laptop. Learned: a photo is checked after the shot because live checking costs battery and complexity, and an outline only lines up if the frame has the picture's shape.
- 2026-10-11 (UI) — History polish: trend chart with the ±2% noise band and baseline, change since last check-in (same noise rule, flagged photos skipped), and a front body map that highlights only what V1 measures (shoulders, waist) with everything else marked not measured; then redrawn as an anatomical figure with a back view where every muscle is grey (front photo only); check-in setup tips became icon tiles with short text (lucide-react added), the review photo grew to nearly full height with icon check chips, and the camera screen got a bigger picture, a bolder outline and a large corner countdown for reading from 2 m; sign-in and sign-up gained an intro panel (track progress from photos, explainable score, photo stays private). Learned: a visual should only show what the data supports; per-muscle ratings without a measurement would be invented numbers.
